# Разбор уведомлений — 10 октября 2026

Просмотрены исходники. Тесты, линтер, проверка типов, сборка и отправка уведомлений на телефон не выполнялись. Доставку на устройстве этот разбор не подтверждает.

## Какие сценарии есть

- «Бумажный альбом»: пользователь выбирает беременность или детский альбом и указывает ПДР/дату рождения. Электронный проект для этого не требуется.
- При создании электронного альбома этих категорий дата также подключает расписание. Временная привязка переносится на настоящий проект.
- «Напоминания»: пользователь может создать своё разовое уведомление с темой, текстом, датой и временем.
- Детское расписание содержит возрастные события и дни рождения с первого по седьмой год; утренний цикл из 31 текста приходит в 09:30.
- Беременность: начало недель, триместры, ПДР, подготовка, выбор имени, помощники и утренние сообщения в 09:00.
- Нажатие на уведомление открывает историю уведомлений. Это работает и для пользователя бумажного альбома.

## Найденные и исправленные ошибки

- После выключения сохранялся старый `notificationId`, поэтому повторное включение не создавало уведомление заново.
- При обновлении служебные строки создавались с новыми id и `enabled: true`; выключение терялось. Фильтр по категории мог удалять личные напоминания.
- Общие `@kids_info` / `@pregnancy_info` позволяли хранить только последнее расписание каждой категории. Теперь расписания хранятся в отдельных строках для каждого альбома; прежние ключи остаются для совместимости с виджетами.
- Временные id альбомов связываются с реальными проектами без повторного включения выключенных настроек. Подключение бумажного альбома не перепривязывается к электронному проекту.
- Анонимный push на дату из выбора обложки дублировал основной планировщик и не имел сохранённого id для отмены. Для беременности и детей используется одна общая очередь.
- Месячные и годовые даты больше не перепрыгивают в следующий месяц: 31 января + месяц = последний день февраля; 29 февраля + год = 28 февраля.
- Неделя беременности считается по календарным дням от ПДР − 280 дней; расчёт принимает нужную дату и не зависит от перехода на летнее время.
- Выбор имени и помощники больше не сдвигаются при каждом открытии. Добавлено отсутствовавшее планирование сумки малыша через три дня после сумки в роддом.
- Бумажный альбом больше не сообщает об успешном подключении при отсутствии разрешения; повторное подключение той же даты использует существующий альбом.
- Удаление проекта отменяет только его настройки и личные привязанные напоминания; другие альбомы продолжают работать.
- При смене пользователя удаляется прежняя очередь, показанные уведомления и локальная история. Планировщик получает отмену, чтобы не дописать старые запросы после выхода.
- Повторные доставки записываются по id запроса и времени доставки. Запись истории последовательная, чтобы параллельные события не затирали друг друга.
- При открытии приложения/истории импортируются сообщения, ещё находящиеся в центре уведомлений телефона.
- Служебные переключатели не отображаются в виджете как отдельные календарные события; показываются ПДР и ближайший день рождения.

## Текущее поведение и границы

- Для каждого альбома доступны отдельные переключатели «утренние сообщения» и «важные моменты». Скрытая после удаления служебная запись остаётся выключенной, чтобы миграция не подключила её снова.
- Настройки синхронизируются вместе со списком напоминаний. Реальная очередь создаётся на каждом устройстве заново, а не определяется наличием чужого `notificationId` из облака.
- При одинаковых дате и событии бумажной/электронной версии один push не удваивается. Утренние приглашения также общие, по одному на время.
- В коде очередь iOS ограничена 64 запросами с учётом посторонних локальных запросов приложения. Резервируется полный месячный цикл детских сообщений; остальные слоты распределяются между ближайшими личными напоминаниями, утрами беременности и ближайшими событиями. Если событий больше, дальние ждут следующего обновления очереди.
- Очередь пересчитывается при запуске, возвращении в приложение, изменении настроек и синхронизации. При неизменных настройках повтор в тот же день пропускается.
- Утра беременности планируются максимум на 14 дней вперёд, в пределах оставшихся слотов, и заканчиваются после ПДР. Их запас продлевается при открытии приложения. Это локальные уведомления, а не серверная доставка на весь срок без запусков приложения.
- Детский цикл 09:30 повторяется ежемесячно без открытия приложения. В коротком месяце отсутствующие числа пропускаются.
- Удалённое из центра уведомлений сообщение, которое приложение ни разу не получило и пользователь не открыл, восстановить из локальной истории нельзя. Для полной истории независимо от запусков нужен серверный источник.

Основные файлы: `utils/albumNotificationCoordinator.ts`, `utils/albumNotificationPreferences.ts`, `utils/localNotificationSchedule.ts`, планировщики беременности/детей, экран бумажного альбома, список напоминаний и обработчики истории.
