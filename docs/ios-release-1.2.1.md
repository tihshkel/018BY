# Выпуск 018BY 1.2.1 (50) через Xcode

Проект для сборки: `/Users/tihonshkel/Desktop/018BY/ios/018BY.xcworkspace`.

## Сборка и загрузка

1. Открыть workspace, выбрать схему **018BY** и **Any iOS Device (arm64)**.
2. Выбрать **Product → Archive**.
3. В Organizer выбрать архив **1.2.1 (50)** → **Distribute App → App Store Connect → Upload**.
4. После обработки сборки выбрать её в версии **1.2.1** в App Store Connect.

Основная схема использует Release для Run и Archive, без локального файла StoreKit. JavaScript включается в бинарник, Metro не нужен. Команда `npm start` для Archive не требуется. Схема `018BY-StoreKit` оставлена для локальных тестов и не используется для отправки.

У приложения и widget extension одинаковые версия 1.2.1 и build 50. Team — `3JY55YHULX`; Bundle ID — `com.tihshkel.x018BY`. Подписание Automatic: Xcode при загрузке выполняет стандартную процедуру распространения через аккаунт разработчика. iOS runtime обновлений — `1.2.1-50`, канал — `production`; старые OTA для runtime `1.2.1` не подходят к этой сборке.

## Поведение оплаты

- Новая покупка передаёт Apple UUID текущего аккаунта 018BY как `appAccountToken`.
- Проверенная покупка с токеном текущего аккаунта открывает печать; токен другого аккаунта требует входа в аккаунт владельца.
- Для активной проверенной транзакции **Sandbox/Xcode без токена** есть кнопка **«Восстановить доступ»**. По явному действию пользователя записывается привязка этой тестовой транзакции к аккаунту на этом устройстве; затем доступ открывается и транзакция завершается. Новый платёж, сброс истории и сервер поддержки не требуются.
- Пассивное получение транзакции не создаёт привязку. После переключения аккаунта локальная тестовая привязка не переносится новому пользователю. Существующий токен Apple имеет приоритет над локальной записью.
- Production транзакция без токена автоматически не назначается текущему аккаунту. Это отдельная миграция с подтверждением владельца, её нельзя заменить локальной записью.
- Тестовая транзакция не записывается в офлайн-кэш реального доступа. Кэш `v3` сохраняет только доступ, полученный из Production транзакции.
- Цена берётся из App Store. При восстановленном доступе недоступная цена не закрывает печать. Электронный PDF остаётся бесплатным.

Sandbox — нормальная среда оплаты для development-signed приложения и TestFlight. Результат тестовой покупки не подтверждает проведение production платежа.

## Данные App Store Connect перед Submit for Review

1. **Business → Agreements → Paid Apps** должен иметь статус **Active**. Заказчик сообщил о принятии соглашений; статус после этого независимо не подтверждён.
2. Покупка **018BY Print Export**, SKU `com.tihshkel.x018BY.export_print_unlock`, тип **Non-Consumable**.
3. В **Review Information → Screenshot** должен быть успешно обработанный скриншот экрана покупки. На последней подтверждённой проверке загрузка предыдущего изображения не была завершена; нельзя считать это поле готовым без повторного просмотра ASC. Для review лучше снять актуальный экран с новой сборки, с ценой и кнопкой покупки.
4. Указать действующий аккаунт проверки в App Review Information. Текст примечаний подготовлен в `docs/app-review-1.2.1.txt`.
5. Добавить покупку и версию **1.2.1** с новой сборкой в **одну draft submission**, затем Submit for Review. Первая Non-Consumable покупка отправляется вместе с новой версией.

Сборка, тесты, покупка на устройстве и отправка на проверку агентом не выполнялись по указанию пользователя. Исходники и настройки подготовлены для самостоятельного Archive; прохождение сборки и оплаты ещё предстоит подтвердить.
